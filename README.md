# VHF Digital Display

A purpose-built, unattended digital display for Veterans Healing Farm (VHF), shown on the Fire TV
television in the building. The display is a web page — published as a static site to Netlify and
loaded on the TV through a browser or off-the-shelf app.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the architecture rationale and
[docs/BUILD_TREE.md](docs/BUILD_TREE.md) for the file tree and milestone plan.

**Status:** the scene engine, playlist, content schema and validator, local admin editor, and the
gallery and calendar adapters are all built, and the site is live. Current work is M0–M1: getting
it onto the television, and making the page survive being left alone for weeks (offline caching via
a Service Worker, content refresh, crash recovery). **The native Fire TV app under `app/` is
dormant** — code-complete for its first phase, never installed, not being developed. See
[docs/BUILD_TREE.md](docs/BUILD_TREE.md) §5.

## Project layout

```
web/        The display itself — scene engine and playlist (HTML/CSS/JS), runs in any browser
content/    Editable VHF content: playlist, settings, artwork, announcements, generated event
            and photo data (source of truth on the PC)
sources/    PC-side adapters for external sources (gallery, calendar, Instagram)
scripts/    Build/publish/validation scripts
admin/      Local-only (127.0.0.1) content editor
dist/       Build output for the Netlify site (git-ignored, generated by scripts/build-site.mjs)
tests/      Tests
docs/       Architecture and planning docs
app/        Android app (Kotlin) — Fire TV shell, DORMANT, see docs/BUILD_TREE.md §5
```

## Preview locally

No Fire TV or Android tooling needed.

```bash
npm run preview
```

This validates every JSON file under `content/`, copies `web/` and `content/` into `dist/`, and
serves `dist/` at `http://localhost:8080`. Add `?diag=1` to the URL for an on-screen debug line
naming the current scene.

**Live site:** https://vhf-firetv-display.netlify.app (Netlify project `vhf-firetv-display`, linked
in `.netlify/state.json`). `publishUrl` in [content/settings.json](content/settings.json) points at
it, and the display polls `<publishUrl>/content/version.json` to detect new content.

## Refresh content from VHF sources

```bash
npm run sync-sources
```

Re-scrapes the VHF gallery and re-fetches the public VHF Google Calendar, rewriting
`content/generated/gallery.json` and `content/generated/events.json`. Inside Claude Code, the
`update-vhf-content` skill wraps sync → build → test → deploy;
[docs/SCHEDULED_CONTENT_UPDATE.md](docs/SCHEDULED_CONTENT_UPDATE.md) is the same sequence written as
a standalone task for a recurring scheduled agent.

## Deploy

```bash
netlify deploy --prod
```

This runs the build command in [netlify.toml](netlify.toml) (`node scripts/build-site.mjs`), which
validates every `content/*.json` file first, and publishes `dist/`. The build never publishes
half-edited content: if anything fails validation the build fails and the previous deploy stays
live. (M2 replaces this hand-run command with `npm run publish`, which also verifies the deployed
version actually advanced.)

## Admin tool (local only)

```bash
npm run admin
```

A local-only server and page at `http://127.0.0.1:8787` for editing content instead of hand-editing
JSON: the playlist (add/reorder/edit/delete scenes), gallery pool weights (max photos, min
resolution, recency bias) with a button to re-run the sync, the gallery exclude list (browse the
current pool and exclude anything needing context an unattended TV can't provide), and
announcements — plus buttons to run the build and deploy.

Every save is validated the same way `build-site.mjs` validates before a deploy — a save that would
break `content/` is rejected and the previous file restored, so this can't produce a broken deploy.
It binds to `127.0.0.1` only and has no auth.

## Requirements

Node 18+ and npm. That's it for everyday work — content edits, preview, and deploys need nothing
else.

## Appendix: the dormant Fire TV app

`app/` holds a Kotlin WebView shell that is **not being developed**. It builds and has never been
installed on the television. Kept because it is the answer if unattended power-cut recovery ever
becomes the blocking complaint — see [docs/BUILD_TREE.md](docs/BUILD_TREE.md) §5.

Building it needs Android Studio (or a standalone Android SDK) with SDK Platform 34, and a JDK 17+.
The gradle wrapper lives at the project root, not inside `app/`.

```bash
JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew assembleDebug
```

The output APK is at `app/build/outputs/apk/debug/app-debug.apk`.

Note that installing it would **not** require ADB or a PC-to-TV connection: the standard path is the
Downloader app from the Fire TV appstore — enable "Apps from Unknown Sources", type a URL, install —
so the APK can simply be published alongside the content on the Netlify site.
